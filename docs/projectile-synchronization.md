# 投掷物同步与视觉平滑

适用版本：Unity 2022.3.62f3、FishNet 4.7.2。

## 配置

- 在非运行状态下切换 `NetworkProjectile.Use Prediction`，等待编辑器完成校验并保存预制体或场景。服务器和客户端必须使用相同配置；不支持运行中切换。
- 编辑器会同步同物体 `NetworkObject` 的预测开关、状态转发及 Rigidbody 预测类型，不使用运行时反射修改 FishNet 私有字段。
- `NetworkProjectile.Graphical Object` 指向物理根的直接子节点 `View`，渲染器放在它下面。Rigidbody 和碰撞体留在物理根，不放在 `View` 下。
- `NetworkObject.Graphical Object` 留空，不附加另一套 `NetworkTickSmoother`、`NetworkTransform` 或自定义视觉插值。预测模式只使用 `NetworkProjectile` 内的阻尼逻辑，不创建 `TickSmootherController`；玩家自由移动仍沿用原有平滑器，玩家被携带时的表现见下文，RPC 既有平滑路径保持不变。
- `Prediction Smoothing` 下的参数只影响预测模式，Rigidbody 插值为 None。预测模式不再使用 `Interpolation Ticks` / `Adaptive Interpolation`；`RPC Presentation.Interpolation Ticks` 仍保留默认 2，沿用原有含义。预制体及 Party 场景已写入新的预测平滑参数，未调整 RPC 参数值。
- 玩家手部锚点继续放在玩家的 `View` 下；玩家 `View` 应保持原有的零位移、单位旋转/缩放绑定姿态，造型偏移放在更下层节点。

## 持有与释放

持有时，投掷物停止飞行平滑、设为运动学刚体并禁用碰撞体。`LateUpdate` 只将 `View` 对齐到玩家已经平滑的手部锚点，不再移动物理根。预测模式在 Replicate 中应用服务器记录的持有姿态；TimeManager 物理的 RPC 模式在 `OnPostTick` 更新物理根；Unity 自动物理的 RPC 模式在 `FixedUpdate` 更新。

物理持有位置和投掷起点通过玩家逻辑根与手部相对姿态计算，不使用玩家视觉平滑造成的世界坐标偏移。视觉持有位置仍使用实际手部世界坐标，并保留投掷物 `View` 原始局部偏移、旋转和缩放。

预测模式释放时保留上一帧实际渲染的手部世界姿态，避免物理 Tick 先移动根节点后污染释放起点。待本帧释放位置应用完毕后，在 `LateUpdate` 分离 `View` 并保留世界缩放；首帧保持释放前的视觉姿态，之后平滑追随物理根加原始局部偏移的目标。持有时不额外阻尼，避免手部已平滑后再次产生跟随延迟。RPC 的释放过渡维持原实现，见下文。

## 预测平滑参数

本节只适用于预测模式，不用于调整 RPC 模式。

| Inspector 参数 | 默认值 | 含义与调节效果 |
| --- | --- | --- |
| Graphical Object | View | 仅含渲染内容的直接子节点。物理根及碰撞体不接受视觉插值。 |
| Position Smooth Time | 0.12 秒 | 位置阻尼响应时间，使用带速度状态的 `Vector3.SmoothDamp`。越大越柔和、追赶越慢；不是固定延迟或保证到达时间。 |
| Rotation Smooth Time | 0.12 秒 | 旋转阻尼响应时间。四元数按最近半球处理，逐分量阻尼后归一化，并修正导数；避免欧拉角跨 ±180° 绕远路。越大转动越柔和，角度落后也越多。 |
| Teleport Distance | 0，关闭 | 世界单位。启用后，物理根在相邻渲染帧间的位置跳变超过此值，就直接对齐位置与旋转并清空阻尼速度。不是视觉误差上限，也没有独立的角度硬切阈值。 |
| Enable Smoothing Logs | 沿用实例配置 | 开启表现与预测误差日志；不改变平滑效果。 |
| Smoothing Log Interval | 0.5 秒 | 日志输出间隔，使用不受游戏时间缩放影响的时钟；不决定平滑更新频率。 |

预测模式每个 `LateUpdate` 只读取本帧最终物理姿态，不在历史重放过程中移动视觉节点。位置与旋转都保留上一帧的阻尼速度，不因碰撞、普通校正或新 Tick 到达而清零；它们会逐渐改变视觉运动，而不是逐次硬对齐。使用 `Time.deltaTime`，暂停时不推进，也不产生零时间除法。客户端停止、组件禁用或销毁时恢复 `View` 的原始父节点、局部姿态和缩放；重新启用时重新初始化阻尼状态。

建议先使用默认值；若更重视柔和，可把位置时间试调至 0.16～0.20 秒、旋转时间调至 0.16～0.24 秒；若落后明显，则逐步降到 0.06～0.10 秒。位置恒速跟随时，稳定落后量大致为“速度 × Position Smooth Time”，因此以 18 单位/秒飞行、0.12 秒设置为例，可能落后约 2.16 单位。这是视觉取舍，不是新的网络延迟。

默认不限制视觉误差、不瞬移，以优先平滑；碰撞时可能出现短暂穿插、转向延后或圆滑的反弹轨迹，命中仍以物理根和服务器为准。若业务需要远距离传送立即对齐，可启用 Teleport Distance，但必须明显大于正常最高速度乘以最差渲染帧间隔，否则低帧率高速飞行也会触发硬切。它不根据积累的视觉落后量判断，因此不会仅因阻尼时间较大而频繁跳变。

## 两种模式

### FishNet 预测

`TimeManager.Physics Mode` 必须使用 TimeManager。保留原有 Replicate、Reconcile 和状态转发；Rigidbody 插值为 None。飞行时由上述脚本阻尼平滑独立 `View`，不使用 FishNet 自带的 smoother。

投掷物继续由服务器控制，不分配给持有玩家。服务器批准拾取、投掷或掉落后，先排入状态转换，在下一次投掷物 Tick 内同时应用运动状态、逻辑姿态、碰撞规则和初速度。持有姿态由服务器采样并随输入传递；观察者回放不读取当前动画手部姿态。玩家移动与投掷物的采样先后仍取决于 Tick 订阅顺序，但各端使用同一条记录姿态。

`ProjectilePredictionState` 记录 Free/Held/Thrown、转换序号、持有者、投掷者及剩余忽略碰撞步数。Reconcile 同时恢复该状态和 PredictionRigidbody，并恢复碰撞体开关及忽略碰撞对。交互用 `_holder` SyncVar 不再决定预测刚体或历史模拟是否处于持有状态；视觉持有状态只在 `LateUpdate` 根据当前模拟结果更新，历史重放不反复启停平滑器。

转换只应用于 FishNet 标记为 Created 的输入，且序号必须比当前状态新。重复或过期转换不会重设位置、重施冲量或清除服务器命中标记；未知未来输入只延续当前物理。序号属于校正状态，回滚到释放前后再重放时，允许合法释放再次施加冲量，不使用永久去重集合。

忽略投掷者碰撞的期限为 `ceil(ignoreThrowerDuration / TickDelta)` 个模拟步，包含释放步。每次模拟前设置碰撞对并消耗一步，下一步开始时到期恢复；回放同样推进步数。使用剩余步数避免直接比较客户端与服务器不同的本地 Tick。换投掷者、重新拾取和停止网络时恢复旧碰撞对。RPC 仍使用自身的实时时钟期限。

命中和击退仍仅由服务器结算，每次新的状态转换重置命中标记。客户端回放不会提交命中结果。本次修改了预测输入与校正数据结构，服务器与客户端必须一起更新；不支持新旧程序混连。

这些改造消除可重复的状态分歧，不保证 Unity 物理在不同机器上逐位一致。与动态玩家或其他物体碰撞时，还取决于它们在重放中的位置、碰撞体及执行顺序；实际联网回拉仍需按下面的验收场景检查。

当前玩家退出按 Destroy 路径验证：投掷者在命令排队后销毁时，释放沿用已记录姿态。如果后续改成玩家池化，应补充 Spawn 身份校验，避免旧命令采样复用后对象的新姿态；本轮没有验证或支持这一复用边界。

### 预测诊断

开启 `Enable Smoothing Logs` 后，按原有日志间隔输出区间最大值：

- `HistoryPositionError`、`HistoryVelocityError`：校正状态与映射到相同客户端 Tick 的本地历史样本之差，排除正常飞行经过的时间。历史最多 256 个 Tick，重放后刷新对应样本；没有匹配样本时不会参与统计。
- `ReplayPositionCorrection`、`ReplayVelocityCorrection`：整轮 Reconcile 和物理重放结束后，相对开始前当前位置、速度的变化。这个值更接近最终需要表现层消化的纠偏量，不等于单次回滚到过去的距离。
- 诊断关闭时不创建历史数组，不逐 Tick 记录；客户端停止时解除事件订阅并清空历史。

启动日志输出 `ScriptSmoothing`、两个 Smooth Time 和 Teleport Distance；预测模式下采样日志中的 `SmoothingActive` 表示脚本是否正在平滑飞行姿态，`Smoother` 应为 False。先分别测试自由飞行、静态墙地反弹、移动玩家碰撞，再增加模拟网络延迟、抖动和丢包。记录误差指标与回放场景；不要仅通过增大阻尼时间判断物理分歧是否修复。

### RPC 事件与本地物理

关闭 NetworkObject 预测及状态转发。仍只广播投掷/掉落事件，各端独立模拟；这不是持续位置快照同步，不保证长时间运动或碰撞后的各端位置完全一致，也不补偿晚加入客户端的历史轨迹。

- TimeManager 物理：在 `OnTick` 施力，Rigidbody 插值为 None，维持脚本管理的独立 FishNet Tick 平滑，固定插值 Tick，不启用 Adaptive。其他预测对象回放时，以 FishNet `RigidbodyPauser` 暂停该 RPC 刚体，回放结束恢复运动学状态、碰撞状态和速度；这不对 RPC 刚体执行 Reconcile。投掷 RPC 只缓存冲量，在回放结束后的实际物理步前消费一次，避免切换运动学状态清掉尚未执行的 AddForce。
- Unity 自动物理：在 `FixedUpdate` 消费投掷冲量并施力，使用 Rigidbody Interpolate，不创建 Tick 平滑器。持有期间关闭 Rigidbody 插值，释放后恢复；释放瞬间的手部视觉偏移在 `Interpolation Ticks × fixedDeltaTime` 内归零，此后仅保留 Rigidbody 插值。

本次自写阻尼改造仅用于预测模式，RPC 的上述行为不变。

不要为了某个 RPC 投掷物修改全局物理模式；同场景仍有 Rigidbody 预测对象时应继续使用 TimeManager。

## 冲锋携带玩家

逻辑根仍在预测模拟中通过 `FollowCarrier` 跟随携带者逻辑根。客户端的 `PlayerCarryController.LateUpdate` 另外将被携带者的 `View` 放在携带者已经平滑的 `View` 前方；携带者没有图形节点时才回退到其逻辑根。这样两人的前后间距不再受各自 Owner/Spectator 插值延迟之差影响，不需要增大距离来掩盖高速冲锋时的视觉落后。

`Carry Distance` 沿用默认 1.3，表示世界单位，不随携带者模型缩放放大。被携带者保留原有模型位置偏移和缩放，朝向仍沿用原有玩家逻辑及平滑器，不强制转向携带者。视觉跟随不写物理根、不新增插值器，也不修改投掷物 RPC。携带脚本使用默认执行顺序 -100，使其 `LateUpdate` 先于默认顺序的投掷物手部跟随。

解除携带或携带者离场时，清除被携带者原有 FishNet 4.x 玩家平滑器的旧队列，保留最后一帧携带姿态，再由后续玩家 Tick 恢复普通平滑，避免旧队列将其重新拉向后方。没有玩家平滑器时直接恢复模型绑定偏移。组件禁用或客户端停止时恢复模型位置，不保留携带覆盖。

本改动仅统一携带时的渲染位置；携带关系仍使用既有 SyncVar，并未加入可回滚的携带关系历史，也没有改变服务器捕获、释放或碰撞判定。跨对象历史回放与实际联机体验仍需单独验收。

## 受击眩晕

玩家眩晕使用 `PlayerStatusController.StunRemainingSteps`，不再比较服务器本地 Tick 与玩家输入 Tick。服务器 `ApplyHit` 将持续秒数换算为 `ceil(max(0, stunDuration) / TickDelta)` 个模拟步；例如 30 Hz 下 0.5 秒为 15 步。参数仍取实际命中投掷物的 `Stun Duration`，本次不修改预制体配置。

每步先按剩余计数判断能否移动、跑跳或冲锋，再递减一次；最后一个眩晕步仍屏蔽输入，下一步恢复。交互也读取同一个 `IsStunned` 状态。缺少输入、观察者未来预测和历史回放均推进计数；搬运期间继续计时，但不改变原有击退衰减行为；因 `StopPrediction` 提前退出、未执行模拟时不消耗步数。

`ReconcileData.StunRemainingSteps` 保存快照时刻的剩余计数，校正时直接恢复，再随历史输入重放逐步递减；不能使用当前剩余值与快照取最大值，否则会延长眩晕。多次实际命中则取“当前剩余步数”和“新命中持续步数”的最大值，不累加，也不让短眩晕缩短长眩晕。计数到零后保持零，击退和重力独立继续模拟。

持续时间以模拟推进为准，不是每次收到校正后重新计时的墙钟时长。玩家校正字段的语义已改变，服务器与客户端须一起更新，不能新旧版本混连。眩晕改造不涉及投掷物 RPC 的实现、配置或视觉平滑。

## 验证

运行 `Tests/Projectiles/Run.ps1`，可通过 `-UnityPath` 指定 Unity 路径。脚本将源码、FishNet、测试和项目配置复制到 `Temp/ProjectileValidation`，使用独立 Unity 批处理运行 EditMode 测试，其中生命周期用例会进入、退出 Play Mode，不关闭现有编辑器。测试结果与日志保存在该临时目录。测试使用真实 Unity Transform/Rigidbody 和本地 FishNet 类型，但不建立客户端/服务端连接。

自动用例覆盖：

- 两种模式下逐帧手持跟随只修改视觉位置。
- 逻辑持有位置不继承玩家图形节点的平滑位移和旋转。
- 释放后恢复原始视觉局部偏移和物理状态。
- 预测开关/状态转发与所选模式一致，旧 Graphical Object 被清空。
- 预测模式使用脚本阻尼平滑位置与旋转，不创建 FishNet smoother、不修改物理目标、不叠加 Rigidbody 插值。
- RPC 原有物理时钟选择与持有/释放插值切换仍通过回归测试。
- 30/60/144 FPS 下跨 ±180° 旋转沿短路径收敛；零 deltaTime 保持姿态且可恢复。
- 30 Hz 阶梯物理目标在 30/60/144 FPS 下连续跟随；飞行旋转后的碰撞纠偏不硬切并最终收敛。
- 默认大校正仍平滑；显式启用瞬移阈值后按物理根帧间跳变触发，不因视觉落后量增大而触发；瞬移清空旧速度。
- 禁用后恢复父节点，重新开始不沿用旧阻尼速度；客户端停止后不再次分离 View。
- RPC 刚体在其他物体回放期间暂停，并恢复速度；客户端停止时解除暂停和事件订阅。
- 两种模式连续三轮飞行/持有，保留非零视觉偏移及根节点的 7 倍缩放；停止客户端后恢复父节点。
- 在独立真实物理场景中验证“收到投掷 RPC → 回放暂停/恢复 → 下一物理步”仍获得预期速度，且冲量只应用一次。
- 移动/旋转手部后释放，不同物理时钟下首帧均保留释放前的视觉姿态。
- 预测 Tick 已经移动物理根后，释放表现仍保持上一帧实际手部姿态。
- 校正恢复持有状态时，同时恢复碰撞体开关，且不改变表现状态。
- 当前 SyncVar 仍显示持有时，历史释放仍可正确执行。
- 重复、过期和未来输入不重复释放；回滚到释放前可重新施加合法冲量。
- 碰撞忽略期限随模拟步推进，回滚可恢复；换投掷者或停止网络会恢复旧碰撞对。
- 静态墙反弹和按相同历史移动的运动学障碍，在校正后重放到相同末态（位置/速度容差 0.02）。
- 校正诊断按同 Tick 样本比较，不把正常飞行的时间差当作状态误差。
- 设置 Spawn 状态后，通过预测输入完成 Held→Thrown，再由 `LateUpdate` 切换视觉状态；验证释放位置、旋转及平滑启用。该用例仍不建立真实网络连接。
- 玩家 CharacterController 停用/重启后，下一回放物理步仍保留忽略碰撞与飞行速度（Unity 2022.3.62f3）。
- 投掷者在释放入队后销毁，仍沿用排队时记录的掉落姿态。
- 玩家受击后，服务器与输入 Tick 存在正负偏差时，0.5 秒仍只屏蔽 15 个模拟步；最后一步、零计数及移动/交互恢复一致。
- 眩晕快照回滚后重放恢复相同位置；零计数校正可立即解除眩晕；无输入、未来预测和搬运期间继续计时，停止模拟不消耗计数。
- 重复命中按剩余时长取最大值；零/负持续时间不会产生眩晕，非整步时长向上取整；客户端不能自行施加命中；击退不会延长输入锁定。
- 玩家逻辑根在前但自身图形插值落后时，被携带者仍显示在携带者图形节点前方；30/60/144 FPS 高速移动和转向下间距保持稳定，不修改逻辑根。
- 携带距离使用世界单位，保留被携带者模型偏移和缩放；携带者没有图形节点时回退到逻辑根。
- 解除携带后清除旧插值队列，保留上一帧姿态并恢复普通玩家平滑；携带者离场、组件禁用或停止客户端时不残留视觉跟随。
